## Таблица операций

| Сценарий | Метод | Путь | Код успеха | Код отказа |
| :--- | :--- | :--- | :--- | :--- |
| Принять посылку на склад ПВЗ | Публикация | `/api/v1/orders/{order_id}/arrive` | 200 | 409 |
| Получить список своих посылок | Получить | `/api/v1/orders?limit=20` | 200 | 401 |

## Пояснения к реализации

1. Постраничный вывод: В списке посылок (GET `/api/v1/orders`) параметр limit по умолчанию равен 20. В списке отображаются только вещи владельца этого ключа (клиент видит только свои посылки).
2. Правило повтора: В операции выдачи заказа (`/issue`) обязателен заголовок Idempotency-Key. Если произойдет сбой и запрос уйдет дважды, второй вызов с тем же ключом не выдаст второй экземпляр товара, а вернет прежний результат (код 200, статус issued).
3. Единый формат ошибки: Для всех адресов используется единая схема Error с полями code, message и request_id.

## События 
Когда заказ успешно выдан клиенту, сервис отправляет наружу вебхук-сообщение:
* Имя события: order.issued
* Поля:order_id, status
* Подпись: Заголовок X-Signature, который учебный получатель проверит.


## Обратная совместимость
* Что можно добавить без ломки старых клиентов: Новое необязательное поле (например, delivery_date в ответе на получение списка посылок).
* Что нельзя менять в версии v1: Нельзя переименовывать поле order_id или менять смысл статусов
